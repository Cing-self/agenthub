# Companion 前台

## 1. 模块定义

Companion 是 AgentHub 面向普通用户的默认前台。

它不是完整控制台，也不是缩小版聊天窗口。它应该更像一个常驻桌面的工作伙伴。

## 2. 产品气质

Companion 必须同时满足两件事：

- `有陪伴感`
- `不打扰`

第一版气质应偏：

- 温暖
- 克制
- 有生命感
- 工作导向

它不能变成：

- 玩具型桌面宠物
- 会频繁乱动的装饰物
- 缩小版大聊天软件

## 3. Companion 的核心状态

第一版建议固定 5 个核心状态：

1. `idle`
   安静待命
2. `working`
   正在执行任务
3. `needs-you`
   需要用户决策或确认
4. `done`
   任务完成，等待审查
5. `blocked`
   任务卡住，继续等待没有意义

所有动画、提示和声音都应该由这套状态机驱动。

## 4. 输入方式

Companion 不需要为不同输入形式做不同产品。

它统一接收：

- 文字
- 语音
- 拖入文档 / 文件
- 视频 / 图像 / 采样帧

这些都应该进入同一个任务入口模型：

- 我希望你做什么
- 我给你的上下文是什么
- 有什么约束
- 什么时候需要我确认

## 5. 展开层

Companion 只负责轻状态和快速唤起。

真正的展开层应该是一个很薄的 review sheet，而不是大窗口。

这个 review sheet 只需要显示：

- 当前任务
- 当前状态
- 最近一次关键进展
- 待确认事项
- 最终结果摘要

## 6. 通知与唤起

Companion 只能在少数高价值时刻主动打扰用户：

- 需要高风险确认
- 需要方向决策
- 任务已完成
- 任务进入明确阻塞

提示方式应分层：

- 默认轻状态变化
- 关键时刻轻提示音
- 真正需要用户时弹出 review sheet

## 7. 个性化

Companion 必须支持外观和表达个性化。

推荐分层：

- Agent 核心
- Companion 外壳
- 用户个性化素材

这样第一版可以先做官方猫咪，也能为未来用户替换形象留空间。

## 8. MVP 边界

Companion 第一版不需要：

- 复杂养成
- 大量互动动作
- 长时间全屏聊天
- 完整配置面板

Companion 第一版必须有：

- 常驻桌面
- 快捷键唤起
- 任务输入
- 状态反馈
- `needs-you` / `done` 时的主动唤起
