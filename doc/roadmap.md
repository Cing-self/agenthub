# AgentHub 路线图

更新时间：`2026-04-06`

## 1. 当前收敛方向

接下来不是继续平铺更多页面和能力，而是把产品往一条主线收：

`交代任务 -> 后台执行 -> 需要时唤起 -> 用户审查 -> 结果沉淀 -> 越来越懂用户`

## 2. 总体节奏表

| 阶段 | 名称 | 当前状态 | 目标 |
| --- | --- | --- | --- |
| Phase 0 | 后台基础设施期 | 已完成大半 | 把 Console、runtime、gateway、bridge、iOS 壳搭起来 |
| Phase 1 | 产品重新定义期 | 正在进行 | 从 console-first 切到 companion-first |
| Phase 2 | 最小前台闭环 | 未开始 | 做出桌面 Companion 和 review-first 交互 |
| Phase 3 | task-first 执行闭环 | 未开始 | 让任务、状态、review、结果成为核心对象 |
| Phase 4 | 记忆中轴 | 未开始 | 让记忆真正影响执行与个性化 |
| Phase 5 | 多模态统一入口 | 未开始 | 把文字、语音、文档、视频统一接入任务系统 |

## 5. 之后按什么顺序做

### Phase 2: 跑通最小前台闭环

目标：

- 做出 Companion 最小形态
- 支持快捷唤起
- 支持一句话 / 语音 / 文件交代任务
- 展示基础状态
- 在 `needs-you` / `done` 时主动唤起

#### Phase 2 清单

- [ ] 做出 Companion 常驻形态
- [ ] 设计 Companion 状态机
- [ ] 做出快捷键唤起
- [ ] 做出轻量任务输入层
- [ ] 做出最薄 Review Sheet
- [ ] 定义 `needs-you` / `done` 唤起规则

#### Phase 2 验收标准

- [ ] 用户可以不打开大窗口就交代任务
- [ ] 用户可以看到 Agent 是待命、工作中还是需要确认
- [ ] 用户可以在任务结束或需要确认时被主动唤起
- [ ] 用户可以在一个很薄的 review 界面里审查结果

### Phase 3: 跑通 task-first 执行闭环

目标：

- 让任务成为一等对象
- 让 review / approval / result 成为前台主交互
- 弱化纯消息式聊天

#### Phase 3 清单

- [ ] 定义任务状态机
- [ ] 定义 review request 数据结构
- [ ] 定义 approval 数据结构
- [ ] 定义 result package 数据结构
- [ ] 在前台展示任务进度而不是消息堆
- [ ] 把关键状态机接入现有 thread / task / session 模型

#### Phase 3 验收标准

- [ ] 用户能清楚知道 Agent 在做什么
- [ ] 用户能在关键节点做决定
- [ ] 用户能在完成时收到结构化结果，而不是一大段消息
- [ ] 任务状态能跨界面、跨入口保持一致

### Phase 4: 记忆成为核心

目标：

- 围绕任务建立短期记忆
- 围绕用户建立长期记忆
- 形成提炼、检索、复盘机制

#### Phase 4 清单

- [ ] 工作记忆落地
- [ ] 用户记忆落地
- [ ] 记忆提炼规则落地
- [ ] 记忆检索时机落地
- [ ] 记忆升级 / 过期 / 修正规则落地
- [ ] 任务完成后的反思记忆落地

#### Phase 4 验收标准

- [ ] 任务中断后能恢复
- [ ] 用户稳定偏好能影响执行方式
- [ ] 过去同类任务的经验会影响本次策略
- [ ] 记忆不只是存档，而是真正影响结果

### Phase 5: 多模态与多入口统一

目标：

- 文字、语音、文档、视频统一进入任务入口
- companion、iOS、channels、remote 共用同一个 Agent 核心

#### Phase 5 清单

- [ ] 统一任务入口协议
- [ ] 语音进入任务系统，而不是独立 voice chat
- [ ] 文档 / 文件进入任务系统，而不是聊天附件思维
- [ ] 视频 / 采样帧进入任务上下文，而不是孤立视频能力
- [ ] iOS、Companion、Feishu、Remote 共享同一状态语义

## 6. 当前优先级

当前最重要的不是：

- 再加一页配置
- 再补一个实验能力
- 再扩一个入口

当前最重要的是：

1. 前台 Companion
2. task-first review 流
3. 记忆中轴

## 7. 明确后置项

下面这些不是不做，而是不是当前优先级：

- [ ] 更多 channel adapter
- [ ] 完整社区 CLI 市场
- [ ] 更完整的 Prompt / Usage 观测平台
- [ ] 视频通话形态本身
- [ ] 极致的 voice duplex 体验打磨

它们都应该建立在主循环先成立之后。
